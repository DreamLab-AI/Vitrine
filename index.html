Save real places

  • For history, games and VR
How
  • Capture: smartphone 4K (best at 4K/60)
  • Ingest: rclone · ffmpeg · frame hashing
  • Optional: iPhone LiDAR, event cameras
Capture: smartphone 4K (reference run used a Pixel 9 Pro); recommend 4K/60, 1/500s shutter. Routed variants: iPhone LiDAR / ARKit, event cameras. Ingest: rclone (Drive/cloud), PyAV + ffmpeg, SHA-256 integrity manifest, multi-sweep unified COLMAP. Partners: DreamLab AI · University of Salford.

Why it is hard

  • Phone video is shaky and blurry
  • A 3D model must be clean
  • Bridging the two is the hard part
How we measure
  • MUSIQ image-quality score
  • Full-resolution sharpness (Laplacian)
  • Motion-blur detector → recapture flag
Quality stack: MUSIQ (via pyiqa) no-reference image quality; Q-Align (alt); Variance-of-Laplacian (full-res 4K sharpness); structure-tensor λ₂ directional motion-blur metric → automatic recapture flag. The honest finding: the limit is motion blur in the capture, not the algorithms.

What you get

  • A full 3D room
  • Each object on its own
  • Ready for a game engine
Formats
  • FBX game assets (Nanite) for Unreal
  • GLB textured objects · .ksplat for web
  • USD kept only for archive
Delivery formats: FBX (baked-texture, Nanite) = the UE deliverable; GLB (PBR object intermediate); .ksplat for web (via @playcanvas/splat-transform); SOG / SPZ / compressed-PLY / PLY; USD/USDA archival only (LichtFeld's native ParticleField prim was dropped for UE). Targets: Unreal Engine 5.8, web viewers (SuperSplat / PlayCanvas).

Smart by design

  • First, check the video
  • Then pick the best way
  • Every video is different
Under the hood
  • Checks quality · coverage · hardware
  • Picks splat vs mesh, and object maker
  • Quality gates: pass / warn / fail
Diagnose: MUSIQ + Variance-of-Laplacian + structure-tensor λ₂ + SfM success + coverage / under-observed % + hardware profile. Router axes: sharpness · coverage · hardware · deliverable → selects the component combo. Guardrails: quality gates (PASS/WARN/FAIL), SOTA preflight (sota_registry).

Step by step

  • Video → points of light → 3D shapes → real textures → game engine
Components
  • Poses → splat: COLMAP + ALIKED + LightGlue → LichtFeld Studio
  • Objects: SAM 3 → TRELLIS.2 / Hunyuan3D-2.1 (textured GLB)
  • Mesh → FBX: CoMe / TSDF → xatlas bake → UE 5.8 (Nanite)
SfM: COLMAP 4.1 + ALIKED + LightGlue (SIFT is the live fallback); alts VGGT, DUSt3R, InstantSplat. 3DGS: LichtFeld Studio v0.5.3 — ImprovedGS+ with MRNF densification + PPISP; alts gsplat, 3DGUT/3DGRUT. Segmentation: SAM 3 (+ SAM 3.1 Object Multiplex), SAM 2; depth-aware mask projection. Objects (image→3D): TRELLIS.2-4B (primary) / Hunyuan3D-2.1 (fallback) / SAM-3D-Objects; view completion FLUX.2-dev (+ Mistral-3), Qwen-Image-Edit, MV-Adapter; DINOv3 conditioning; served on ComfyUI. Scene mesh: CoMe / gsplat-TSDF (Open3D) / MILo / 2DGS / PGSR / SuGaR. Cleanup+texture: MeshCleaner → xatlas → Blender Cycles bake. Engine: Unreal Engine 5.8 + Nanite + NanoGS.

By the numbers
  • In: ~13.6k frames → ~1,650 kept · MUSIQ ≈31
  • Splat: 30k steps → 4.0M → 1.55M Gaussians
  • Objects: 8 found → 3–4 clean (TRELLIS.2), 4K PBR
  • Room: ~81k-face mesh, 2048² texture
  • One 48 GB GPU · splat ~25 min
INPUT: 1× 4K/30 handheld walkthrough (Pixel 9 Pro), multi-pass; ~13,600 frames → ~1,650 kept (original run 1,200 → 600); RGB only. Footage MUSIQ ≈ 31 (below ~19 = abandon); 0% under-observed, ~90 cameras per point; blur-aware selection lifts bottom-quartile sharpness +20–38%. OUTPUT: SfM 600/600 registered (locked 750), ~290k–367k sparse points, ~1.0–1.16 px reproj; 3DGS 30,000 iterations → ~4.0M Gaussians → SuperSplat-clean 2.48M → pruned 1.55M for UE; SAM 3 found 8 objects → 3–4 reconstructed cleanly (TRELLIS.2 beat Hunyuan3D) at 4096px PBR, real scale (chair 60cm, ladder 210cm); room TSDF cleaned to ~51k verts / 81k faces, 2048² albedo (planarity 72% — capture-limited, shipped as NanoGS splat hero). Compute: RTX 6000 Ada 48GB; 3DGS ~25 min, CoMe ~59 min, ArtiFixer 14B peak 45.5GB. The clean win is the OBJECTS; the room is capture-limited → recapture (4K/60) is the lever.
